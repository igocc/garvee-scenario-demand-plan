6共购验证怎么算

把"一起被提到"变成"一起被买"。

先把 SKU 映射到场景品类

用第 5 步的 coverage.csv 建一张映射表 sku_category(sku, scenario, category)，按品类而不是单个 SKU 统计，否则样本会太稀。

同时看两个口径

GARVEE 多是大件商品，一单里同时买两件的情况少，所以除了"同单"，还要看"同一个客户 90 天内先后买"。

-- 表名为占位，按实际订单表替换
WITH lines AS (
  SELECT o.order_id, o.customer_id, DATE(o.created_at) AS d, m.category
  FROM order_lines o JOIN sku_category m USING (sku)
  WHERE m.scenario = 'garage'
    AND o.created_at >= DATE_SUB(CURRENT_DATE(), INTERVAL 365 DAY)
    AND o.financial_status IN ('paid','partially_refunded')
),
same_order AS (            -- 口径 1：同单
  SELECT a.category AS cat_a, b.category AS cat_b, COUNT(DISTINCT a.order_id) AS n
  FROM lines a JOIN lines b ON a.order_id = b.order_id AND a.category < b.category
  GROUP BY 1, 2
),
same_customer AS (         -- 口径 2：同客 90 天内
  SELECT a.category AS cat_a, b.category AS cat_b, COUNT(DISTINCT a.customer_id) AS n
  FROM lines a JOIN lines b
    ON a.customer_id = b.customer_id AND a.category < b.category
   AND ABS(DATE_DIFF(a.d, b.d, DAY)) <= 90
  GROUP BY 1, 2
)
SELECT * FROM same_order ORDER BY n DESC;

每个组合输出四个数

指标算法用来判断
共购单数（或客户数）同时含 A、B 的订单数样本是否够，太少就标"无数据"
A→B 附加率含 A 且含 B ÷ 含 A买了 A 的人里有多少也买 B，决定推荐方向
B→A 附加率含 A 且含 B ÷ 含 B反方向，两者常常不对称
提升度（lift）P(A 且 B) ÷ (P(A) × P(B))> 1 说明比随机更常一起买；只看附加率会被热销品误导

共购门槛（最少多少单才算"已验证"）不预先拍脑袋定：第 2 周先看两个试点的分布，再在评审会上定，写入 decisions.md。共购是相关关系，不说明套装会带来增量。

8内容生产规范

页面结构跟着问题走，不跟着内部叙事走。

L0 场景枢纽页

  • 例：Garage Makeover Guide
  • 按子场景分流
  • 回答"需要哪些东西""大概多少钱"

L1 子场景 / 区域页

  • 例：Garage Storage & Organization；Bathing Zone
  • 一页覆盖一个子场景的设备清单

L2 决策页

  • 例：Will a Portable AC Work in a Garage?；Hydraulic vs Electric Grooming Table
  • 承接 PAA 里的高频对比题

每页固定模块顺序

  1. 问句式标题：直接用问题表里经过校验的原句。
  2. 首句答案：一句能单独摘抄的结论，带条件（犬只体重、车库面积、是否有窗）。
  3. 决策表：承重、尺寸、功率 / BTU、价格带、适用人群。
  4. 适合和不适合：明确写哪种情况不该买（如 78.9 lb 以上的狗不用夹式臂）。
  5. 真实场景图：说明文字与画面一致。
  6. 搭配建议：只写第 7 节验证过或标明"待验证"的组合。
  7. FAQ：本页剩余问题。
  8. 证据：规格来源、评价数、质保、更新日期。

上线前验收清单

检查项通过标准
问题来源每个问句标题至少 2 个来源对得上，其中 1 个来自站内真实用户（GSC 问句、站内搜索、客服、评论）
规格一致页面上每个数字都能在对应商品页找到，逐项对照
定位准确家用款不写成专业款；液压不写成电动
安全内容涉及丙烷 / 燃气取暖器的页面必须写通风和一氧化碳风险
无未核实承诺批量采购、组合询价、安装服务等，业务确认真实提供后才写
技术正文、表格、FAQ 由服务器直接输出；JSON-LD 与可见内容一致；图片 alt 与画面一致

12风险与边界

  • 需求指数是估算：来自 DataForSEO，只统计含场景词的问法；品类之间有重叠，只能排序，不能相加。
  • 共现不等于共购，共购不等于增量：套装上架前必须走第 6 节；上架后的效果要用对照或同比判断。
  • 搜索结果每次都会变：PAA、商品卡、AI 摘要都是单次采样。
  • 样本稀疏：大件商品同单共购少，所以同时看同客 90 天；仍不足的组合如实标"无数据"，不硬上。
  • 抓取合规：抓取 Amazon 页面违反其使用条款。首期优先用官方购物篮分析报告；抓竞品需业务明确批准。
  • 页面不保证被引用：本方案改善的是结构和证据，AI 是否引用不在站点控制范围内。
  • 价格会变：第 5 节价格按 2026-10-27 查询，执行时以付款页为准。
